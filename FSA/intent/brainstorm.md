# fa_core 需求规格

FlashAttention 单 tile 计算核。本文为 `fa_core` 的完整模块需求与验收依据。

## 1. 概述

- **定位。** `fa_core` 是一个单 tile 注意力计算核（DUT）：边界上接收 query / key / value
  三个矩阵，产出注意力输出矩阵 `O`。
- **要解决的问题。** 用硬件算一个注意力 tile `O = softmax((Q·Kᵀ)/√d)·V`，支持可选 causal
  掩码，fp16 输入/输出、fp32 内部运算，结果与可信软件参考（PyTorch
  `scaled_dot_product_attention`）在容差内一致。首要考察的是功能与数值正确性，同时须完成
  时序收敛并满足单 tile 延迟门限（§7）。
- **范围边界（明确排除，不属本模块）：**
  - 片上存储 / SRAM 分 bank 与 DMA
  - 总线接口（AXI / TileLink）与内存映射集成
  - 指令译码 / ISA 前端、指令驱动的控制生成
  - 多 tile flash 在线重缩放（跨 tile 携带 running max / running sum）。本核只算单 tile，
    tile 内 softmax 完整
  - 多头 / batch 注意力（单 tile = 单头；多头由调用方外层循环处理）
  - causal 之外的掩码模式：padding 掩码、滑动窗口、任意逐位置掩码均不支持，只支持全注意力与 causal

## 2. 功能需求

### 2.1 核心算法

对一个 tile，给定 `Q [Br×d]`、`K [Bc×d]`、`V [Bc×d]`：算 `S = (Q·Kᵀ)/√d`；对 `S` 按行做
数值稳定（减去行最大值）的 softmax 得到概率 `P`；再算 `O = P·V`，并以 `P` 的行和归一化。
causal 模式屏蔽未来位置。

### 2.2 锁定的数值参数

- **维度：** `Br = Bc = d = 4`（Q / K / V / O 均 `4×4`）。
- **精度：** 输入/输出 fp16（E5M10）；内部累加与 softmax fp32（E8M23）。
- **中间量 `P` 的精度：** `P` 在 exp 之后立即舍入到 **fp16**；行和归约与 `P·V` 矩阵乘消费
  同一份 fp16 `P`（累加仍在 fp32），使归一化的分子 `P·V` 与分母 `rowsum(P)` 处在同一精度域。
- **缩放：** `1/√d = 0.5`，作用于 `Q·Kᵀ` 分数。
- **exp 的实现基：** `exp` 由 `exp2` 实现，`exp(x) = 2^(x·log2e)`，`log2e = 1.44269504…`。
- **两个常数的乘入位置由实现方选择**：对正标量缩放，row-max 是同态的，因此
  `0.5` 与 `log2e` 可以分别乘入、也可以合并为单一常数 `log2e/√d` 在 exp2 前一次乘入，
  只要数学等价。F-01 的 `S` 指其数学值，不约束实际乘入位置。
- **舍入模式：** 所有 `fp32 → fp16` 转换（`P` 的舍入与 `O` 的输出）用就近偶数（RNE）。
- **安全 softmax：** 指数化之前减去每行最大值。
- **归一化顺序：** 在 `P·V` 之后归一化，即 `O = (P·V)·r`，其中 `r = 1 / rowsum(P)`。
- **分块：** 单 tile，无在线重缩放。
- **行和下界（不会除零）：** 减最大值后每行必含一个 `exp(0)` 项。分段线性 exp2 的 0 段端点
  对齐时 `fp16(exp2(0)) = 1.0`，此时 `rowsum(P) ≥ 1`；端点不对齐时该项 ≥ 0.999。两种情况下
  倒数都有界，不会除零（F-05 无除零负例）。
- **输出范围：** `O` 为 `V` 各行的凸组合，`|O| ≤ max|V|`，故输出转换无需饱和逻辑。

### 2.3 工作模式

`causal_en` 在第一个 `qkv_in` beat 被接受（`valid && ready`）的那一拍锁存，自那拍起直到
`done` 为无关值（核不在操作中途重新采样，连发的每个 tile 各自锁存自己的模式）。
`0` = 全注意力，`1` = causal（屏蔽 `j > i` 的位置）。

### 2.4 数值 / 边界策略

- 输入假定为合法 fp16（无 NaN、无 Inf），非规格化数按 FTZ 冲零。不做非法输入检测，也没有
  `error` 状态输出；输入合法性由调用方保证，非法输入属未定义行为。
- **causal 掩码用预偏置实现：** 在 row-max 之前把 `j > i` 的分数偏置为一个大负常数，使一份
  已偏置的 `S` 统一流过 row-max、exp、row-sum。该常数由实现方钉死并在设计文档中记录，须同时
  满足：
  1. 低于所有可能的真实分数，使被掩位置不会成为行最大值（这是"整行取 max"等于"未掩位置取
     max"的前提）；真实分数的下界由受限的激励范围给出（§8）；
  2. 大到让 `exp2` 把它下溢为精确 `0`（被掩 `P_ij = 0`），同时仍落在 exp2 步可表示的约减
     参数范围内。

  数据通路中不出现 IEEE `-Inf`；causal 下对角 `j=i` 恒保留，无全掩行。

七条特性全部为必备（P0）。

## 3. 顶层接口

事务级边界；内部数据通路的调度属实现细节，隐藏在该接口之后。

| 接口组 | 信号 | 方向 | 宽度 | 时钟域 | 协议 | 作用 |
|--------|------|------|------|--------|------|------|
| clk | `clk` | 输入 | 1 | clk | — | 时钟 |
| reset | `rst_n` | 输入 | 1 | clk | — | 复位（异步、低有效） |
| qkv_in | `qkv_in_data[63:0]` / `qkv_in_valid` / `qkv_in_ready` | 输入 | 64 bit/beat | clk | valid/ready | 数据（一个矩阵行 = 4×fp16 每 beat；共 12 beat，顺序 Q→K→V，每个矩阵按行号序、行 0 在先；K 按行主序送入，数据通路内部自行转置以算 `Q·Kᵀ`） |
| cfg | `causal_en` | 输入 | 1 | clk | 电平 | 模式选择（在操作开始 = 第一个被接受的 `qkv_in` beat 采样） |
| o_out | `o_out_data[63:0]` / `o_out_valid` / `o_out_ready` | 输出 | 64 bit/beat | clk | valid/ready | 数据（一个输出行 = 4×fp16 每 beat；共 4 beat，按行号序、`O` 行 0 在先） |
| status | `busy` / `done` | 输出 | 1 / 1 | clk | 电平 / 脉冲 | 状态 |

- **背压：** 阻塞式，不丢弃、不覆盖。装载期核拉高 `qkv_in_ready`；排空期保持 `o_out_valid`
  直到消费方就绪。
- **握手规则（按方向）：** 输入侧允许生产方在 beat 被接受前撤销 `qkv_in_valid`（即允许气泡，
  见 SC-006）；输出侧 `o_out_valid` 一旦拉高须保持到该 beat 被接受，其间 `o_out_data` 保持
  稳定。`o_out_valid = 0` 时 `o_out_data` 为无关值。
- **`done` / `busy`：** `done` 在最后一个 `o_out` beat 被接受（`valid && ready`）的下一拍给出
  恰好一拍的脉冲，`o_out` 被背压期间不给出；`busy` 在 `done` 脉冲的同一拍拉低。
- **单时钟域**（`clk`）：无跨时钟域。

### 3.1 beat 位打包与模块名

两条 `*_data` 总线均为小端：

- `*_data[63:0]` 承载一个矩阵行 = 4 个 fp16 元素，元素 `j` 位于 `[16·j +: 16]`
  （元素 0 → `[15:0]`，元素 3 → `[63:48]`）。
- 每元素的 fp16 字段布局：`{sign[15], exp[14:10], mantissa[9:0]}`（E5M10）。
- beat 顺序：输入 12 beat = `Q` 行 0–3、`K` 行 0–3、`V` 行 0–3；输出 4 beat = `O` 行 0–3。
- 顶层 RTL 模块名：**`fa_core`**。

### 3.2 模块划分

单 RTL 模块：共享数据通路、中央阶段调度器、中间寄存器组、I/O 握手全部收敛在一个模块内，
没有跨模块连线。阶段之间的数据流（`S` / `P` 矩阵与 `m` / `l` / `r` 向量）属模块内部事项，
记录在实现方的设计文档中。

## 4. 时钟与复位

| 时钟 | 频率 (MHz) | SDC 周期 (ns) | 关系 | 是否生成 | 作用 |
|------|-----------|---------------|------|----------|------|
| clk | 100 | 10.0 | primary | 否 | 主时钟 |

- **100 MHz / 10 ns 是硬性指标**：综合与 STA 均在 10 ns 周期下进行，`timing_slack_ns ≥ 0`
  为硬门限（§7）。
- 跨时钟域：无（单域）。
- 复位：`rst_n`，异步、低有效。单复位，无释放次序要求。

## 5. 架构约束

- **架构选型：共享数据通路 + 单模块。** 一套共享的算术资源（fp16 乘 / fp32 累加的 MAC，兼做
  row-max 的比较选择、exp2 步、倒数步与归一化乘法）在各阶段之间时分复用，由中央阶段调度器
  驱动。阶段序列：
  `load → QK → row-max → exp2 → row-sum → reciprocal → PV → normalize → drain`。
  每阶段把结果写入中间寄存器组（`S` 4×4、`P` 4×4，以及 `m` / `l` / `r` 4×1 向量），下一阶段
  从中读取。softmax 的非矩阵乘算子与矩阵乘共用同一套算术资源。
- **阶段内的并行度与流水级由实现方决定**，在满足 §7 门限的前提下自行选择；每阶段周期数须在
  设计文档中给出。
- 不采用 4×4 脉动阵列 + 阵内 softmax 融合的路线，也不采用按算子拆成多个 RTL 模块 + 中间缓冲
  的全流水划分。划分原则：只有当跨模块接口与时序都简单清晰时才拆分，否则收敛为一个模块。
- exp2 采用分段线性近似；倒数单元的实现结构由实现方选择。段数、位宽、迭代次数受 §8.1 的
  精度预算约束。

## 6. 时序场景

| 场景 ID | 接口 / 模式 | 触发 / 激励 | 期望结果 | 时序约束 | 例外 / 负例 |
|---------|------------|------------|----------|----------|-------------|
| SC-001 | 全注意力 | `causal_en=0`；连续送 12 beat Q→K→V | 核完成后 `o_out` 发出 4 beat，等于 `softmax(QKᵀ/√d)·V`，在容差内与参考一致 | `single_tile_latency ≤ 80` 拍 | — |
| SC-002 | causal | `causal_en=1`；同样的装载 | `O` 与参考的 causal 注意力一致；`j>i` 的位置贡献为 0 | 同 SC-001 | 被掩位置通路被激励 |
| SC-003 | 连发 | tile A 排空期间请求 tile B | 12 beat 收满后至 `done` 之前 `qkv_in_ready` 保持低（装载期为高，见 §3），B 不得插队；操作串行化，无数据破坏 | 每 tile 原子 | 重叠请求不得破坏在飞 tile |
| SC-004 | 输出背压 | `o_out_ready` 保持低 | `O` 保持在输出寄存器中；排空停顿；不丢失、不覆盖 | 阻塞式 | 消费方停顿处理 |
| SC-005 | 任意阶段复位 | 在任意阶段（装载 / 计算 / 排空）拉低 `rst_n` | 操作中止；状态清零；`busy=0`；无残留部分输出；释放后干净重启 | 异步复位 | 复位打断任意阶段的事务 |
| SC-006 | 输入背压 | 生产方在装载中途撤销 `qkv_in_valid`（beat 之间有气泡） | 核保持 `qkv_in_ready` 等待；不丢 beat、不重复 beat；下一个有效 beat 到来即续传；结果不受影响 | 阻塞式 | 装载期生产方停顿处理 |

### 6.1 事务级波形

```text
clk    _|‾|_|‾|_ ... (100 MHz, 10 ns)
qkv_in [Q0 Q1 Q2 Q3 K0 K1 K2 K3 V0 V1 V2 V3]
busy   _|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|_
o_out  _______________________________________________________[O0 O1 O2 O3]__
done   ____________________________________________________________________|‾|_
```

**阶段映射：**

- **装载：** 12 个行 beat（Q→K→V）在 `qkv_in` valid/ready 下被接受；`busy` 自第一个被接受的
  beat 起为高。装载期 `qkv_in_ready` 为高。
- **计算：** `busy` 为高；共享单元按阶段序列推进（QK、row-max、exp2、row-sum、倒数、PV、归一化）。
- **排空：** 4 个输出行 beat 在 `o_out` valid/ready 下发出；排空全程 `busy` 保持为高。
- **done：** 单拍脉冲标志本 tile 完成；`busy` 在 `done` 脉冲同一拍落下。

### 6.2 单 tile 延迟的定义

`single_tile_latency` 是原子操作延迟：从第一个 `qkv_in` beat 被接受，到最后一个 `o_out` beat
呈现（`valid`），在 `qkv_in` 持续有效且 `o_out_ready` 持续为 1 的条件下测量（SC-004 / SC-006
造成的消费方 / 生产方停顿拍数不计入）。该延迟与数据无关，门限为 ≤ 80 拍（§7）；确切数值由各
阶段周期数决定，须在设计文档中给出。

## 7. PPA 目标

- `timing_slack_ns ≥ 0` @ 10 ns（100 MHz）—— **硬门限**，综合与 STA 在该周期下均无违例。
- `single_tile_latency ≤ 80` 拍 —— **硬门限**（定义见 §6.2）。
- `area_um2` —— 仅报告，不设面积预算。
- `power_mw` —— 仅报告。

## 8. 验收与验证

- **黄金参考：** PyTorch `scaled_dot_product_attention` 在 fp32 下求值，输入用与 DUT 完全相同
  的 fp16 量化后的 Q/K/V（提升到 fp32，使 DUT 与参考看到逐位相同的输入），采用 SDPA 默认的
  `1/√d` 缩放（= 0.5，与 DUT 一致），`is_causal` 与 `causal_en` 对齐；期望的 `O` 由带种子的
  参考脚本离线生成，在 testbench 中比对。
- **验收：** 对全部 16 个 `O` 元素取逐元素绝对误差，要求 `MaxErr < 1e-2` 且 `MAE < 1e-3`。
  **按 tile 判定**：两个界都在每个 tile 的 16 元素 `O` 上检查，回归通过的条件是每一个 tile
  （所有种子、定向边界用例、两种 `causal_en` 模式）都同时满足两个界。
- **激励：** 随机合法 fp16 Q/K/V（带种子），裁剪到 N(0,1) 的 ±4σ，使分数范围、exp2 的参数
  范围、causal 偏置的余量都有界且可推导。另加定向边界用例（多个相等最大值的行；causal `i=0`
  的单项行；全相等输入；分数幅度大 / softmax 尖峰的行）以及两种 `causal_en` 模式。
- **可选调试手段：** 可以写一个逐步的软件模型把失败定位到某一阶段（`S` / `m` / `P` / `l` /
  `O`）。判据只是 I/O 上的容差检查。

### 8.1 误差预算

参考在同一份 fp16 激励上做 fp32 softmax，输入量化误差相互抵消，所以误差底就是 `O` 的 fp16
舍入（RNE 半 ulp，随 `|O|` 所在二进制区间变化：`|O| < 1` 时 ≤ 2.4e-4，`|O| ∈ [2,4)` 时
≤ 9.8e-4）。`MAE < 1e-3` 是实际起约束作用的子门限。

`MaxErr` 的 1e-2 预算在各贡献项间分配：分段线性 exp2 ≤ ~5e-3，倒数与 fp16 舍入占其余。
MAE 预算同理（底 ~1e-4 量级，exp2 / 倒数 / 舍入分摊余下）。本节是预算分配，不是验收判据；
判据只有上面两个界。

### 8.2 其他验收门

- RTL 用 Verilog-2001，整体可综合；空 stub、blackbox 视为未实现。
- UVM testbench 功能验证，行 / 条件 / 状态机 / 翻转覆盖率均 > 90%。
- lint / CDC clean（0 Error、0 Warning）。

## 9. 须由实现方钉死的项

1. causal 偏置常数的取值与依据（须满足 §2.4 的两条要求）。
2. exp2 在缩放 + 减最大值之后的输入域。
3. exp2 与倒数的近似方法、位宽与误差分配。若倒数采用"种子 LUT + 1 次 Newton 迭代"，种子位宽
   须 ≥ 5 bit，以把误差压到 fp16 噪声底之下。
4. 每阶段周期数与 `single_tile_latency` 的实测值（须 ≤ 80 拍）。
5. F-01–F-07 的正常路径 / 边界用例 / 负例落到具体激励，以及各特性的可观测量与参考规则。
